## 1. Sentence Structure Preferences

**核心偏好：短斷句 + 空行製造呼吸感，避免長逗號連句。**

- **短句為主，首句常 15 字內落地**。拋完第一個 frame 就空行。
- 複合想法**拆多行、多段**，極少用「因此」「所以」「而」當連接詞。以空行取代連接。
- 常見句式模板：
  - `X：Y / X：Y / X：Y`（對照列表）— Codex CLI 遷移那篇 7 項全走這個
  - `昨天 A，今天 B`（時間對照）— Vibe Coding Day 2 整段用此節奏
  - `不是 A，是 B`（否定對照）— 「**軟體會變多，不是變少。**」
- 愛用**破折號（—）** 當「補料 / 加註」符號，而非一般轉折：
  - "行員的工作也從「數鈔票」轉成「賣金融商品、處理貸款、經營客戶關係」。**—**"
  - "一份內容兩邊能共用。"（用 `—` 獨立成段）
- 結尾常用「短句金句 kicker」收束：
  - "**軟體會變多，不是變少。**"
  - "**根本是救星吧😎**"
  - "**AI 從「工具」變成「永遠上班的員工」這件事，正在悄悄發生😎**"

**Evidence：** ATM 貼文、DeepMind 貼文、Codex 對照貼文皆呈現此模式。

## 2. Tone Switching Patterns

**核心：嚴肅分析打底 + 結尾自嘲放鬆。中段不帶情緒，結尾才漏口氣。**

- **研究 / 數據段落：理性、克制，幾乎不用 emoji**
  - "單一 agent：每 1,000 tokens 完成 67 個任務 / 中央式多 agent：21 個 / Hybrid 團隊：14 個" — 純陳述
  - "在 Similarweb 上的數據顯示：..." — 沒有情緒詞
- **個人日誌 / 生活：吐槽 + 中斷尾**
  - "看來薪水小偷還當得不太夠格😂"
  - "跟晚上研究了ㄧ下日本觀光列車都一覽無遺惹"
  - "我要來去睡覺惹，晚安😴"
- **推薦 / 宣傳：配自嘲淡化推銷感**
  - "**BD神器！上線第一天就有user！因為就是我女友XD**"
  - "反應熱烈的話，我再加快釋出的腳步！💪"
- **切換時機：通常在「論點已給 → 段落結束」時**。不會在推論中間突然切。嚴肅→輕鬆是 gradual（論完後放手），不是 abrupt。
- 嚴肅 vs 輕鬆比例：粗估 **4:6**（輕鬆略多，但爆文幾乎都落在嚴肅側）。

## 3. Emotional Expression Style

| 情緒 | 典型表達 | 例證 |
|---|---|---|
| 開心 / 得意 | 不直說，用反問 + emoji | "是不是有質感多了呢🎉？" |
| 驚訝 / 發現 | 「居然」「沒想到」「欸」 | "OpenAI **居然**出了個 Claude Code 的 plugin"；"哇 **沒想到**大家對這主題反應這麼熱絡🎉" |
| 興奮 / 讚嘆 | "超" "猛" "神器" "救星" + `😎` / `🎉` | "**最猛的是**，每次查詢的 token 用量只需要原本的 1/71.5！"；"這根本是**救星**吧😎" |
| 無奈 / 自嘲 | 括號 + `😂` | "（AI 幫我做的，漏掉不要怪我）"；"雖然這樣就不那麼 Vibe 了😂" |
| 保留 / 不確定 | 「我覺得」「應該會」「可能」「挺的」 | "**我覺得** Claude Code 其實就是 Agentic AI 的代表作" |
| 挫折 / 拖延 | 自嘲法則/定律式框架 | "我怎麼每次都在趕死線呢？" → 引帕金森定律 |

**情緒強度：中等且穩定。** 會用強詞（神器、超猛、根本是）但極少用驚嘆號串（！！！）或全大寫。情緒峰值通常**壓在一句金句**，而不是整段渲染。

## 4. Knowledge Presentation Style

**核心姿態：「我在用，我順手整理一下分享」——不教書、不炫技、不商業推銷。**

- **技術名詞保留英文，幾乎不翻譯**：Claude Code、MCP、webhook、subagent、knowledge graph、skill、LLM 都原文上場
- **預設讀者是開發者 / AI 工具早期採用者**：不解釋「什麼是 agent」，但會解釋「多 agent 會 overhead」
- **通俗化技巧：對照表 + 具體數字 + 生活類比**
  - 對照：Codex CLI ↔ Claude Code 7 項差異
  - 數字：1/71.5 token、67 vs 21 vs 14 任務、0.42 → 0.13 相關係數
  - 類比：ATM → AI；n8n → 自動化；「組織一個專業團隊」→ subagents
- **自信語氣 = 把證據攤開，讓讀者自己判斷**，而不是「你必須」
  - "白話翻譯：對一般人來說，粉絲數幾乎不能預測..."
  - "規模夠大，可以說點結論。"
- **分享立場時用「我」不用「應該」**：
  - "**我覺得** Claude Code 其實就是 Agentic AI 的代表作"
  - "**我就**把它拿來做我的部落格寫文系統"
- **Evidence 密度高**：一篇 tutorial 貼文平均會出現 2–3 個具體數字/指令/工具名。

## 6. Common Analogies and Metaphor Style

**來源域偏好：科技史 > 工具 > 日常動作，幾乎不用體育/遊戲/金融比喻。**

| 類型 | 範例 | 長度 |
|---|---|---|
| 科技史類比 | ATM → AI（「ATM 確實讓每間分行需要的行員從 20 人降到 13 人...」） | 擴展一段 |
| 工具擬人化 | subagents → "組織一個專業團隊"；Conway → "永遠上班的員工 / 數位員工" | 一句帶過 |
| 地理空間 | "遠在雲端上的 n8n 無法輕易碰觸的地方" | 一句 |
| 日常動作 | "釣魚而非魚"；"複製大法" | 一句 |
| 直譯口語 | "本地版 n8n"；"救星"；"神器" | 一詞 |

- **比喻**重具體**，**輕抽象**。會把歷史場景完整寫出（ATM 那篇描述 1969 紐約、1970 30 萬行員、2000 年 60 萬人），而不是丟一個抽象類比就走。
- **同一類比重用風險**：「救星」「神器」「本地版 n8n」已接近過度使用閾值。
- 幾乎沒有：文學/詩意類比、遊戲機制類比、運動賽事類比。

## 7. Humor and Wit Style

**核心類型：自嘲 + 旁白吐槽。幾乎沒有諷刺、毒舌、迷因。**

- **位置偏好：**
  - **括號內**：「（AI 幫我做的，漏掉不要怪我」「（週末早上做了下這個 APP，跟晚上研究了ㄧ下日本觀光列車都一覽無遺惹」
  - **句尾 emoji kicker**：`😂` `😎` 接在結論後
  - **結尾輕鬆收**：「我要來去睡覺惹，晚安😴」
- **頻率**：31 篇中約 **20 篇帶輕度幽默**，但沒有一篇走段子式。
- **Emoji 主力**：`😂`（自嘲）、`😎`（自信/酷）、`🎉`（慶祝）三兄弟；`🤔` `💡` `🚀` `👋` `👇` 配角。
- **避免**：`🥺` 裝可憐、`😭` 誇張難過、`🤡` 自貶小丑、`😤` 憤怒、`🙄` 翻白眼。
- **結論寫完順手吐槽自己** 是招牌動作：
  - "（滑脆除了放空耍廢外，健康很重要"
  - "雖然這樣就不那麼 Vibe 了😂 但懂了之後會 Vibe 得更順"

## 8. Self-Reference and Audience Address

- **自稱**：「我」（最主力）／「自己」（次之）／「我的」（描述作品時）
- **稱呼讀者**：
  - 「**大家**」最多（「大家有沒有覺得」「跟大家分享」）— 群體稱呼
  - 「**你**」用在 hook 與 CTA（「你以為 Claude Code 只能寫程式？」「比起問他答案是什麼，或許問他該如何去找出答案會更好」）
  - 「**你我**」偶用，親切感加倍（「**你我**的世界裡，這件事根本不成立」）
- **「我們」極少**：幾乎不用 in-group framing。Unity 槓桿目前未啟用——這是未被使用的空間。
- **對特定子群的稱呼**：
  - 「每天在燒 Claude Code token 的人」
  - 「小咖帳號 / 一般帳號」
  - 「一人公司創業或自媒體」
- 沒有固定暱稱（不會喊「朋友們」「各位夥伴」「家人」這種）。

## 9. Taboo Phrases

以下類型**從未在歷史資料中出現**，是本 voice 明確的 anti-pattern：

- ❌ **正式書面語**：「因此」「綜觀之」「由此可見」「可謂」「堪稱」
- ❌ **網紅式誇張自貶**：「本人廢到笑」「跪求」「老鐵們」
- ❌ **過度感性抒情**：「此刻的我」「深深感動」「內心澎湃」「不禁 X 起來」
- ❌ **驚嘆號堆疊**：「！！！！」連打；全句驚嘆
- ❌ **全大寫 / 全英文 hook**：沒有 "BREAKING:" / "INSANE:" / 英文 headline
- ❌ **營銷八股 CTA**：「立即免費領取」「錯過後悔」「限時倒數」「名額有限速搶」
- ❌ **過度可愛語尾**：「喵」「啾咪」「嗚嗚」；ASCII 顏文字 `(´・ω・\`)`
- ❌ **教學口吻**：「各位朋友請注意」「小編今天要告訴你」「今天要教大家」
- ❌ **絕對化斷言**：「百分之百」「絕對」「永遠不會」（除非後面接自嘲）

## 10. Paragraph Rhythm Micro-Features

| 維度 | 偏好 |
|---|---|
| 首句長度 | **10–20 字**，極少超過 30 字。常單行獨立成段 |
| 開頭段落 | **1–2 句**落地。不鋪陳。 |
| 中段發展 | 證據堆疊（數字 / bullet / 對照表），用空行分組而非連接詞 |
| 結尾段 | **單句金句 kicker + emoji**，或 **連結 + 留言 CTA** |
| 段落連接 | **空行為主**，極少「因此」「所以」「而」 |
| 段落數 | 中位數 **6 段**，爆文多落在 5–8 段 |
| 特殊符號 | `—`（獨立成段當 aside / 補料）、`👇`（指向留言 / 下文）、`・`（清單項） |
| 白空間 | 高密度使用，讀起來像呼吸節奏 |

**節奏範本（爆文常見）：**

```
[短句 hook，<20 字]

[第一層論點，1–2 句]

[數字 / 對照清單，3–5 項]

[解釋段，2–4 句]

—

[金句結尾 + emoji]
```

## 11. Comment Reply Tone Characteristics

> 10 則 author reply，樣本偏小，結論僅供參考。

**與原文相比：**

- **更直接、更工程師感**：原文會鋪 1–2 句 context，reply 通常直接上結果或連結
- **補料多、客套少**：沒有「感謝大家支持」這種開場；直接把「第二個發現」「還有幾個小眾帳號」丟出來
- **連結常裸貼**：往往一行 URL，頂多加一句 "專案 repo" 或「XX 新聞」
- **熱烈反應 → 升級承諾**：會順勢宣布系列計劃、邀請留言入 waitlist
- **Emoji 頻率稍降**：比原文略少。像「哇 沒想到大家對這主題反應這麼熱絡🎉」是相對多的例外

**Reply 長度分佈（10 則）：**

- 短：2 則（裸 URL）
- 中（1–3 句）：3 則
- 長（整段補料）：5 則 — 最常見型態

**固定模式：**
- ✅ 熱烈互動時加一個 `👋` 收尾
- ✅ 爆文的 reply 幾乎都是「補料 + 升級承諾」雙層
- ❌ 沒有固定開場問候語（不會說「嗨～」「謝謝」）

## 12. Quick Reference Summary for `/draft`

### 核心節奏 ✅

- 首句 < 20 字，單行獨立成段
- 開頭段 1–2 句落地，不鋪陳
- 中段用**空行分組**，不用連接詞
- 證據密度高：每篇 2–3 個具體數字或工具名
- 結尾**單句金句 kicker** + `😎` / `😂` / `🎉` 其一
- 中位篇幅 **150–400 字**（sweet spot）；別超過 400 字

### 語氣 ✅

- 嚴肅打底 + 結尾自嘲，**切勿反過來**
- 「我覺得」「其實」「居然」「沒想到」是招牌
- 情緒強度中等：可以「超」「神器」，但**不要驚嘆號堆疊**
- 技術名詞保留英文
- 破折號 `—` 獨立成段當 aside 可用

### 讀者稱呼 ✅

- 「大家」優先，「你」次之
- 「我們」慎用（非本 voice 主力）
- 特定子群可以點名：「每天在燒 Claude Code token 的人」、「一般帳號」

### Humor ✅

- 位置：**括號內** > **句尾 emoji** > **結尾整句自嘲**
- 頻率：輕度幽默，不段子化
- Emoji 三兄弟：`😂` `😎` `🎉`

### 比喻 ✅

- 科技史 / 工具擬人化 / 日常動作
- 具體 > 抽象（場景式描寫而非詩意類比）
- 避免「救星 / 神器 / 本地版 n8n」短期內重複

### 結尾 Patterns（擇一）

1. **金句收**：「軟體會變多，不是變少。」
2. **連結附留言**：「連結附留言 👇」
3. **軟邀請**：「有興趣的可以去看看～」
4. **升級承諾**：「反應熱烈的話，我再加快釋出的腳步！💪」

### 絕對避免 ❌

- 正式書面語（因此 / 綜觀之）
- 感性抒情（此刻的我 / 深深感動）
- 驚嘆號堆疊、全大寫
- 營銷八股 CTA（立即領取 / 錯過後悔）
- 教學口吻（小編今天要告訴你）
- 可愛語尾（喵 / 啾咪）
- 誇張自貶（本人廢到笑 / 跪求）

### 結構骨架（可複用）
