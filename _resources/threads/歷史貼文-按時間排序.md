OpenAI 居然出了個 Claude Code 的 plugin，讓你在 Claude Code 裡直接叫 Codex出來幫忙。

簡單講，它把 Codex 包成一組 slash 指令，讓你邊用 Claude 邊可以：

 ・叫 Codex 幫你做 code review
 ・更狠的 adversarial review，專門挑設計決策的洞
 ・Claude 卡住解不出來的，丟給 Codex 當背景 agent 跑（這招叫 rescue）
 ・還能查背景任務進度、隨時中止

最有感的是 rescue 這招——Claude 跟 Codex各自有擅長的地方，用一個取代另一個太可惜，讓它們互相救援反而合理。

Google DeepMind 跟 MIT 在 2025 年 12 月發了一篇論文，用 180 種 agent 配置做了大規模實驗，得出一個很清楚的結論：

agent 數量的報酬會遞減，很多時候 1 個 agent 的 token 效率，比一整個團隊還好。

他們測了 4 個 benchmark、5 種架構、3 個 LLM 家族。
規模夠大，可以說點結論。

先看 token 效率：

- 單一 agent：每 1,000 tokens 完成 67 個任務
- 中央式多 agent：21 個
- Hybrid 團隊：14 個

派一個團隊做事，token 效率掉到單一 agent 的三分之一，嚴重的時候只剩五分之一。原因也很直接——hybrid 架構光是 agent 之間互相講話、協調進度，就產生了 515% 的額外 overhead。

1969 年，美國第一台 ATM 裝在紐約的一間銀行裡。

當時所有人的直覺反應都一樣：銀行行員要被取代了。

結果呢？

1970 年，美國有大約 30 萬名銀行行員。
到了 2000 年初，ATM 已經超過 40 萬台——行員人數不降反升，變成 60 萬人。

怎麼回事？

ATM 確實讓每間分行需要的行員從 20 人降到 13 人，省了 35%。
但因為經營成本變低了，銀行反而瘋狂開分行，都市地區的分行密度增加了 43%。
行員的工作也從「數鈔票」轉成「賣金融商品、處理貸款、經營客戶關係」。

自動化沒有消滅工作，它改變了工作的內容，然後創造了更多需求。

—

AI 讓寫程式變便宜了。

但便宜不代表需求會消失——反而是那些「一直想做但做不起」的東西，現在做得起了。

以前養不起工程師的小公司，現在可以有自己的內部工具。以前需要開發團隊才能做的 workflow，現在一個人就能搞定。

軟體會變多，不是變少。

Threads 數據觀察 01 : 我是不是要先衝粉絲數，互動才會起來？

最近把 6,335 個帳號、接近 20 萬篇貼文攤開來看，好奇想知道這個答案。

第一次算，數字看起來還行（0.42）。
但我總覺得哪裡怪——那幾個百萬粉大號的數字實在太誇張，會不會整個相關性都是他們撐出來的？
把他們拿掉，只看我們這種小咖帳號，掉到 0.27。
再校正一次分布不均，結果掉到了 0.13。

—
白話翻譯：
對一般人來說，粉絲數幾乎不能預測你這一篇會有多少互動。
那個「粉越多互動越高」的印象，幾乎完全是金字塔頂端那幾個大號撐出來的幻覺。
把他們拿掉，你我的世界裡，這件事根本不成立。
—

所以如果你還在一般帳號的區間，這件事的意思是：
別再把「衝粉絲」當經營主軸了。
真正決定這篇會不會被看到的，是內容本身——題材、寫法、時機、跟受眾合不合。粉絲數頂多是加分，不是保險。

—
這是第 1 篇，資料還很多，我自己也很好奇接下來會看到什麼，有看到有趣的東西會再來分享。
