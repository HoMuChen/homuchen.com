# Threads 寫作指南（@homuchen.build.ai）

結合三個來源：網路上 2026 年的 Threads 經營建議、**自己帳號的實際數據**、`homuchen-writing-style` 的語氣。三者衝突時，以自己帳號的數據優先，其次才是網路建議。

格式與規則（不加掰掰、連結不放主貼文、數字照實、內容邊界）以 repo `CLAUDE.md` 的 Threads 段落為準，這份不重複列出細節。

## 自己帳號的數據（2026-10-15，33 篇主貼文）

| 貼文 | 觀看 | 型態 |
|------|------|------|
| Claude Code token 救星！Graphify… | 12,084 | 單則 270 字＋回覆放連結 |
| 大家有沒有覺得，AI 生成的網頁都有「AI 味」？ | 10,152 | 單則 380 字＋實測比較圖 |
| DeepMind × MIT 論文：agent 數量報酬遞減 | 3,766 | 單則 370 字＋1 則回覆補充 |
| 一句話！用 Claude Cowork 建成 Notion 看板 | 1,732 | 單則 145 字 |
| 部落格改寫的 7 則長串文（淨資產儀表板） | 24 | 長串文，主貼文只是鋪陳 |

- 全部中位數 146 觀看；200 字以下中位數 265，最高。
- 爆的都是**「一個新東西／一個實測結果／一個研究數字」＋自己的一句觀點**，主貼文本身就把重點講完。
- 從部落格硬改寫的長串文表現最差：主貼文在鋪陳、重點藏在後面幾則，沒人點開。
- 主貼文帶連結的不一定會死（AI 味那篇有連結還是破萬），但中位數較低；**連結一律放回覆**比較保險。
- 問句結尾、真心想聽答案的貼文回覆數明顯較多（DeepMind、Graphify 各 13 則回覆）。
- 樣本小（33 篇），以上是方向，不是定律。之後持續用 Insights 驗證。

## 網路上的共識（多為行銷部落格，Meta 官方沒有公布細節）

- **回覆是最重要的訊號**，而且是發文後的前幾小時：問一個真的想聽答案的問題，發文後第一小時回每一則留言。
- **前兩行決定一切**：超過約 4 行會被折疊，鉤子要在前兩行。
- **一篇一個 topic tag**（不是 hashtag 堆疊），要真的符合內容。
- **連結對觸及的影響有爭議**，常見做法是放第一則回覆，主貼文本身要能獨立提供價值。
- **穩定比量多重要**：每天 1–2 篇、固定節奏，勝過一天狂發。
- **原創優先**：自己的實測、數據、觀點比轉述新聞更容易被推。

## 格式選擇

預設寫**單則**，只有內容真的是步驟或清單時才用短串文。

| 格式 | 何時用 | 長度 |
|------|--------|------|
| **單則**（主力，約 3/4） | 一個觀點、一個發現、一個數字、一個小技巧 | 80–350 字 |
| **單則＋1 則回覆** | 主貼文講完重點，回覆補一個細節，或放「完整文章」連結 | 主貼文同上，回覆 ≤150 字 |
| **短串文**（約 1/4 以下） | 步驟、清單、前後對照，拆開才講得清楚 | 3–5 則，每則 ≤350 字，主貼文本身也要有料 |

## 一篇文章拆成多個 idea

一篇部落格不是一則 Threads，而是 **3–6 個可以各自獨立成立的 idea**，分開發表、隔幾天一則。挑 idea 的角度：

1. **反直覺的數字或結果**：「排名第 7，CTR 卻只有 0.36%」
2. **踩過的坑**：「我原本以為免費版就夠，結果……」
3. **一個馬上能用的小技巧**：一個 prompt、一個設定、一個指令
4. **前後對照**：以前怎麼做 → 現在怎麼做，差在哪
5. **觀點或金句**：文章裡最有態度的那句話
6. **提問**：把文章的核心問題丟回給讀者，「你們都怎麼……？」

每個 idea 都要**不看原文也看得懂、看完就有收穫**。不要寫成「預告片」，要寫成「一個完整的小東西」。同一篇拆出來的 idea，開頭鉤子和句型都不要重複。

## 鉤子（前兩行）

從自己爆過的貼文歸納出來的開頭：

- **「X 救星！」＋新東西**：「Claude Code token 救星！最近看到一個開源工具叫 Graphify……」
- **共鳴提問＋實測**：「大家有沒有覺得，AI 生成的網頁都千篇一律、有個『AI 味』呢？🤔」
- **權威來源＋具體數字**：「Google DeepMind 跟 MIT 發了一篇論文，用 180 種 agent 配置做了大規模實驗……」
- **一句話成果**：「一句話！用 Claude Cowork 直接建成 Notion 任務看板」
- **反差數字**：「Google 搜尋排名第 7，CTR 卻只有 0.36%。」

不要用「今天想跟大家分享……」「你知道嗎？」這種空的開頭。第一句就要有具體的東西：工具名、數字、結果、場景。

## 收尾

- 約一半的貼文用一個**真心想聽答案的問題**收尾（「你們都怎麼記帳？」），不要每篇都問，也不要問「你覺得呢？」這種空問題。
- 另一半用**一句觀點**收尾（「AI 不是不會做，只是你給他的 context 不夠多」）。
- 要導流到部落格時，主貼文最後一句可以說「完整做法放在留言～」，連結放回覆。
- 不加「掰掰～👋」。

## 穆穆的語氣（Threads 版）

- 口語、像跟朋友聊天：「酷吧😎」「就是這麼簡單～」「根本是救星吧」
- 適量 emoji（一則 1–3 個）：😂 😎 🎉 🤔 👇 ✅
- 可以自嘲：「不是因為錢太多😂」
- 短句、多換行，一段 1–3 行，方便手機閱讀
- 數字要具體、照實，不灌水，也不要淡化
- 不要寫成廣告：介紹工具時講自己怎麼用、結果如何，不要喊「必學」「神器」

## Topic tag

每則主貼文放一個 topic tag，用自己帳號已經在用的，讓同類內容累積在同一個主題：

- `claude code`：Claude Code 相關
- `AI觀察`：AI 新知、研究、趨勢
- `Vibe Coding`：用 AI 做出網頁或工具
- `AI Agent`：自架 agent、自動化
- `台股`：股票、交易、FinMind
- `理財`：記帳、資產、Google Sheet 理財工具
- `Notion`、`Google Sheet`：特定工具

topic tag 不能有 `.` 和 `&`。

## 發完之後（給人，不是給排程）

- 發文後第一小時盡量回每一則留言，這是觸及最大的槓桿。
- 每兩週用 Threads Insights 看一次：哪種開頭、哪種格式、哪個 topic 表現好，更新上面的數據表。
