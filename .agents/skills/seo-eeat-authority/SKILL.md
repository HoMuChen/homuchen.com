# SEO E-E-A-T 與品牌權威

Google 與 LLM 在「該引用誰」這件事上越來越嚴格。這個 skill 提供：50+ 個 E-E-A-T 具體訊號清單、7 步驟 Brand SEO 框架、語意/實體 SEO 做法、Share of Search 計算、品牌提及 audit 流程。詳細方法論見 `REFERENCE.md`。

---

## When to Use

- 審核一篇文章「權威感夠不夠」
- 為整個網站做 E-E-A-T 檢核
- 規劃個人品牌 SEO 策略（讓作者本人變成 entity）
- 想讓文章被 AI 引用但一直被跳過
- 新網站要建立信任訊號（about、author bio、credentials）
- 文章內容 OK 但就是輸給權威站（同一關鍵字）

---

## 核心觀念：從「Default Trust」到「Earned Allowlist」

AI 時代的新典範：
- **過去**：預設信任，做壞事才失信
- **現在**：預設不信任，要主動賺取「allowlist」資格

這代表個人部落格比企業站更難，但也更有機會（因為人格化權威是 AI 更重視的訊號）。

## E-E-A-T 50+ 訊號四象限檢核表

用這個清單對自己的網站/文章逐項打勾。缺哪一類，就補哪一類。

### Experience（實作經驗）
- [ ] 有真實 case study（不是推測是實作）
- [ ] 有原創數據（實驗、測試、調查）
- [ ] 作者 byline 有具體身份與角色
- [ ] 有「我們實測過」的敘事（過程、踩雷）
- [ ] 有截圖、照片、影片證據
- [ ] 有具名個人分享具體經驗（不是「匿名團隊」）
- [ ] 有 before / after 視覺對照
- [ ] 業界年資具體寫出（例：「寫了 10 年 Node.js」）
- [ ] 有 hands-on 互動的證據（不只是講別人做過什麼）

### Expertise（專業深度）
- [ ] 被業界專家引用（同儕認可）
- [ ] 有比競品更進階的方法論文件
- [ ] 原創研究 / 資料分析
- [ ] 有相關認證、學歷、證書公開
- [ ] 技術深度（複雜概念有清楚解釋）
- [ ] 有會議演講紀錄
- [ ] 出書 / 主要刊物發表紀錄
- [ ] 有訪談其他專家（不是只自己講）
- [ ] 提出自己的框架 / 心智模型
- [ ] 技術工具使用深度

### Authoritativeness（外部權威）
- [ ] 在 Knowledge Graph 中被辨識為獨立 entity
- [ ] 非品牌關鍵字也排得上（代表主題權威）
- [ ] 高權威站的 backlink（質比量重要）
- [ ] 媒體報導、新聞曝光
- [ ] Wikipedia 頁面（如果達到 notability）
- [ ] Wikidata 條目
- [ ] 被 AI Overviews / LLM 引用
- [ ] 得過獎或業界認證
- [ ] 業界平台上有講者檔案
- [ ] 顧問 / 專家小組成員身份
- [ ] Google / Apple Maps / Bing 商家檔案一致
- [ ] 品牌搜尋量 MoM 成長
- [ ] 利基領域的 Share of Search 佔優

### Trust（信任基礎）
- [ ] 有完整的法律頁（隱私、條款、免責）
- [ ] 作者 bio 明確可見
- [ ] 聯絡資訊（地址、電話、Email）
- [ ] HTTPS
- [ ] 透明的商業註冊 / 驗證
- [ ] Google / Trustpilot / 業界平台的正面評論
- [ ] 專業的設計與 UX（不廉價）
- [ ] 所有外部資訊都有清楚出處
- [ ] 明確揭露利益衝突或聯盟行銷關係
- [ ] 有公開的勘誤 / 更正政策
- [ ] Schema markup 正確實作
- [ ] 所有平台品牌一致（頭像、名稱、介紹）
- [ ] 內容有持續更新的證據
- [ ] 與可信組織的合作關係

## Brand SEO 7 步驟框架（Ryan Law）

規劃品牌 SEO 從 0 開始時用。

1. **定義品牌基礎（5W1H）** — Who / What / When / Where / Why / How，寫成 Brand Bible
2. **Audit 既有品牌曝光** — 品牌搜尋量、Knowledge Graph、商家檔案、unlinked mentions、AI Overviews 提及
3. **研究受眾搜尋行為** — 什麼情境會搜？在哪個平台搜？品牌字 vs 非品牌字比例？
4. **分析競爭對手定位** — 他們的品牌關鍵字、Share of Search、主題分佈
5. **實作 SEO 改善** — Google Business Profile、作者專頁、Organization schema、語意 landing page、NAP 一致性
6. **主動推播品牌** — PR、社群參與（Reddit、業界論壇）、媒體合作、原創研究
7. **監控視覺化儀表板** — 月度追蹤品牌搜尋量、Share of Search、unlinked mention 速度、AI Overviews 提及、backlink 成長

## Entity SEO：變成 Google / LLM 認得的 entity

**Entity 定義**：Google 能獨立識別的「東西」—— 組織、人、產品、地點、概念。

### 讓自己變成 Entity 的主要訊號

1. 建立 Google Business Profile（即使是個人品牌也可以）
2. 爭取 Wikipedia 條目（最強，但要符合 notability）
3. 建立 Wikidata 條目（結構化 entity 資料）
4. 社群 profile 一致（LinkedIn、Twitter、Instagram 等）
5. 建立主題權威（在特定利基領域被認得）

### 次要訊號

1. 內部連結策略性設計（展現關係）
2. 所有地方用同一個名稱（不要變體）
3. 高權威站的主題性提及
4. 所有 Google 會顯示的數位資產（影片、圖片、產品）都建立
5. 自然使用語意相關詞（主題生態）
6. Schema.org 結構化資料（Organization、Person、Product）

### Recognition 指標（怎麼知道成功了）

- 搜尋品牌名有 Knowledge Panel
- 出現相關 entity 的 Knowledge Card
- 圖片 / 影片在搜尋結果顯眼位置
- 相關搜尋建議包含你的 entity
- "People also ask" 連到你的主題
- AI Overviews 引用你的品牌

### 繁中特別考量（HoMuChen 適用）

確保跨語言一致：繁中、簡中（如需）、英文、拼音/羅馬拼音。

## Semantic SEO：展現主題深度

### 三支柱

**Pillar 1: Brand（機器可辨識的身份）**
- 準確的 Organization schema
- 明確定義核心主題與關係
- 連結到相關主題 cluster
- Google Business Profile / Knowledge Graph 資料正確

**Pillar 2: Content（主題連結）**
- 覆蓋完整主題，不是關鍵字變體
- 用 Entity-Attribute-Value 模型思考
  - **Entity**：核心對象（產品、服務、地點）
  - **Attribute**：讀者搜尋的特性（尺寸、材質、功能）
  - **Value**：具體選項（大、鋁製、快）
- 相關主題內部連結（別把概念孤立）

**Pillar 3: Technical（機器友善）**
- 語意化 URL（描述主題，不是 ID）
- 乾淨的 IA
- Schema markup
- 對齊使用者意圖的主題分類
- 有描述性的內部連結 anchor text

### Page-Level Topic Gap 關閉流程

1. 找出「以前排得上、現在掉了」的關鍵字
2. 對比競品在這個主題的覆蓋深度（用 Content Grader 類工具）
3. 找出缺漏的概念連結（例：「遠端工作」應該要連結「時區管理」）
4. 策略性更新，把先前分離的概念串起來
5. 鎖定主題 cluster，不是單一關鍵字

## Share of Search 公式與監控

**公式**：
```
你的品牌搜尋量 ÷ (你 + 主要競品品牌搜尋量總和) × 100%
```

**範例**：你 20,000 + 4 個競品共 30,000 = 50,000 總和
→ 20,000 / 50,000 = **40% Share of Search**

**衍生指標**：
- **Category Penetration** = 你的品牌搜尋量 ÷ 整個類別搜尋量
- **Momentum** = 品牌搜尋量的 MoM 變化
- **AI Overview Share** = 你在 AI 摘要中出現次數 vs 競品

**提升 5 招**：
1. 執行品牌建立活動（病毒內容、合作、難忘時刻）
2. 分析競品被提及的地方（backlink analysis）
3. 主打非品牌關鍵字但強調你的定位
4. 監控 mention 機會（unlinked brand alerts）
5. 優化品牌字的 on-site 體驗

## 品牌提及 Audit 8 步驟

每季一次：

1. **Benchmark 既有曝光** — 獨立頁面數、引用網域數、流量、MoM 趨勢
2. **分析 AI 搜尋影響** — sentiment、AI 引用來源
3. **偵測流失的 mentions** — 季比、Wayback Machine
4. **改善弱 mentions** — 要求補連結 / 改 anchor text
5. **修正錯誤資訊** — 網路上的錯誤版本都要更正
6. **Benchmark 競爭對手** — 他們被誰提？你沒被誰提？
7. **發掘未開發機會** — 利基權威站、產業清單、評論
8. **監控 + 報告** — 月度 alert、季度回顧

### Unlinked mention 轉換策略

找到 DA > 40 的站提及你但沒連結 → Outreach（引用具體段落、提供 anchor text 建議、附上 URL）→ **轉換率 10-20%**

## 在 AI 時代怎麼與眾不同（三支柱）

**LLM 是「整個網路的平均值」**。贏過 LLM 的唯一方法是產出 LLM 生不出來的內容。

### Pillar 1: Experimentation（原創數據）
- 自己做產業調查，發布原始數據
- 分析自家公司資料（客戶結果、趨勢）
- 測試方法論，做實驗
- 做業界基準報告
- **ROI**：原創數據內容排名更久、引用更多、轉換價值高 6x

### Pillar 2: Experience（第一手經驗）
- 只寫自己實作過的主題
- 訪問有經驗的從業者（不是二手整理）
- 提供具體證據（截圖、照片、實作紀錄）
- 分享有量化結果的案例
- **「我投入過，不是只是推薦」**

### Pillar 3: Effort（勞力密集的護城河）
- 互動式網頁、漫畫、長圖
- 紀錄片式影片系列
- 書、長篇內容
- 自製工具（calculator、小程式）
- **「難以複製 = 保值」**

### ❌ 要避免的 Anti-patterns

- 從 5 個來源 remix 資訊（這是 AI 的強項，你贏不了）
- 寫自己沒做過的主題（讀者一看就知道）
- 純「文字 + 庫存圖片」的 vanilla 內容
- 只求速度跟低成本
- 模糊的軼事、沒有證據的推論
- 不標示出處
- 大量發文但沒做品質把關

## 實用 Mental Models

### 要採用
- **第一原理思考** — 回到根本真理，不要追產業謠言
- **80/20 法則** — 20% 的頁面帶來 80% 流量（優先處理那 20%）
- **Red Queen Theory** — SEO 沒有「做完就好」的終點，持續優化才能維持

### 要避免
- **Local Maxima Trap** — 微幅改進代表可能卡在局部最佳，要考慮根本轉向
- **沉沒成本** — 低績效專案不要因為「已經投入很多」繼續做
- **確認偏誤** — 主動找反證，不要只找支持自己的證據
